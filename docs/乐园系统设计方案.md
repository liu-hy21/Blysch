# 乐园系统设计方案

Blysch 情侣本子里的「乐园」：两人共用一座星露谷式俯视小屋。宠物按当天固定位置出现在院子或室内；家具由兔、牛各自等级解锁，全部摆进同一座屋。

本文是实现依据。未写进本文的能力默认不做。

---
kais
## 1. 目标与边界

### 要做

- 「我的」增加入口「乐园」，进入共用小屋。
- 俯视像素布景（HTML + CSS），分室外、室内两张图，点屋门进出。
- 你的宠物和对方的宠物出现在随机房间；同一天位置不变。
- 每 3 级解锁 1 件家具；已解锁的全部出现在屋里对应格子。
- 守护页增加「家具」模块，展示该宠物已拥有 / 未解锁的家具。

### 不做

- 可走动、碰撞、时间流逝、季节天气。
- 玩家自己拖家具、扩建房间。
- 羊、鹿、狗、猫的专属家具图鉴（你们当前是兔和牛）。
- 新数据表。家具与位置都由等级、物种、日期算出来。
- 画布引擎、瓦片地图、独立 PNG 场景大图。

## 2. 入口与空态

| 位置 | 行为 |
|------|------|
| 「我的」列表 | 新增一项：标签「乐园」，说明「居住地」，链到 `/me/park`，图标用 `Moon` 或 `House`。排在心愿之前。 |
| 返回 | 顶栏 `BackBar`，`href="/me"`，标题「乐园」。 |
| 双方都没有宠物 | 仍显示空屋（室外默认）。不站宠物。文案：「还没有人认养宠物。」 |
| 只有一方有宠物 | 屋在，只有那一只出现。 |
| 未登录 | 走现有 `(app)` 布局，与其它「我的」子页相同。 |

页面用 `PageStack`，链入 `nav-forward`，返回 `nav-back`。

## 3. 场景与进出

视角：星露谷物语式俯视（略俯、硬边像素、不是等距 3D）。场景是一层定位好的像素块，不是可走格子。

### 3.1 室外（默认）

一屏院子：

- 四周篱笆，中间草地。
- 画面中上方是小屋外观（墙、屋顶、一扇可点的门）。
- 门是唯一进室内的入口，`min-h-11`，`aria-label="进屋"`。

当天抽到「院子」的宠物站在门前草地；抽到室内的宠物在室外不可见（不在窗户里做剪影，避免两套坐标）。

### 3.2 室内

一张平面图，不切房间场景：

- 左：客厅
- 右：卧室
- 下沿中央：门口，点了回室外，`aria-label="出门"`

抽到客厅 / 卧室的宠物站在该区域；抽到院子的在室内不可见。

室内外用本地 state 切换（`scene: "yard" | "house"`），不改 URL。刷新回到室外。

### 3.3 宠物当日房间

每个已存在的宠物独立抽一次，候选：`yard` | `living` | `bedroom`。

```
seed = hash(coupleId + petId + YYYY-MM-DD)
room = ["yard", "living", "bedroom"][seed % 3]
```

同一天反复进出位置不变。第二天再抽。两只宠物可以抽到同一房间，挨着站，不重叠到完全盖住（横向错开）。

显示名写在精灵下方，字号 11px。

## 4. 家具与解锁

### 4.1 规则

```
ownedCount = floor(level / 3)
```

| 等级 | 件数 |
|------|------|
| 1–2 | 0 |
| 3–5 | 1 |
| 6–8 | 2 |
| … | … |
| 30 | 10 |

满级 30，每只最多 10 件。两只宠物的已解锁家具全部摆进共用屋，格子写死在图鉴里，不能拖。

家具不入库。`serializePet` 增加 `furniture: { id, name, desc, scene, unlockLevel, locked }[]`，算法与技能列表相同。

其它物种（羊鹿狗猫）`furniture` 为空数组；守护页显示「这个物种还没有家具图鉴。」乐园里只摆兔、牛已解锁的件。

### 4.4 视觉

家具是 CSS 像素块：硬边墨线、木色 / 金 / 花粉，体积小、能认出是什么即可。不单独做精灵表。未解锁的件不渲染（屋里不留虚位）。

点家具不必弹详情。守护页才看名字和说明。

## 5. 守护页「家具」模块

放在「技能」和「背包」之间。看自己的、看对方的都显示。

结构对齐技能列表：

- 已解锁：名字 + 一句 `desc`；右侧小字标「室内」或「室外」。
- 未解锁：名字「？？？」+ `Lv.{unlockLevel}`，整行降低透明度。
- 标题「家具」；副文案「每 3 级一件，会摆进乐园小屋」。

对方页仍只读。没有图鉴的物种显示一句空态，不渲染空列表。

## 6. 页面结构与数据流

```
src/lib/dream-furniture.ts     兔/牛图鉴、ownedCount、slots
src/lib/pet-rules.ts           serializePet 附带 furniture
src/app/(app)/me/page.tsx      入口链接
src/app/(app)/me/park/page.tsx          拉双方宠物，PageStack
src/app/(app)/me/park/dream-client.tsx  室内外切换、摆家具、摆宠物
src/app/(app)/pets/pets-client.tsx       家具模块
```

`park/page.tsx` 与守护页相同：`requireUser`，读自己的 `pet` 和对方的 `pet`，`serializePet` 后交给客户端。

客户端只做：

1. 用 `coupleId + petId + todayKey()` 算房间（`coupleId` 由服务端传入）。
2. 按 `scene` 过滤家具槽和宠物。
3. 点门切换 `scene`。

不新增 API。照料、喂食升级后 `router.refresh()`，乐园下次进入即可看到新家具。

## 7. 交互与动效

- 门外、门内点击进出。无滑动手势切场景。
- 宠物沿用 `PixelPet`，室外 `scale={2}`，室内 `scale={2}`，可轻微 `translate` 呼吸（`prefers-reduced-motion: reduce` 时关掉）。
- 场景切换用现有 `ViewTransition`：室内外包一层 `enter="fade-in" exit="fade-out" default="none"`，不做整页滑入（这是同页状态，不是路由层级）。
- 触控区域门 ≥ 44px。家具不拦截门的点击。

---

## 8. 无障碍

- 场景容器 `role="img"`，`aria-label` 概括：「室外院子」或「室内客厅与卧室」，并带上「某某在院子 / 客厅 / 卧室」。
- 门是 `button`，不要用没有名字的 `div`。
- 家具纯装饰，`aria-hidden`。名字在守护页读。

---

## 9. 验收

1. 「我的」能进乐园，返回回到「我的」。
2. 默认室外；点门进室内；再点门回室外。
3. 有兔、有牛时，当天各在三个房间之一；刷新当天位置不变；改系统日期（或等到第二天）会变。
4. 等级 1 的宠物屋里没有它的家具；升到 3、6、9… 后对应件出现在指定场景。
5. 两只的家具同时出现，槽位不叠成一团。
6. 守护页「我的 / 对方的」都能看到该宠物的家具列表；未解锁为问号。
7. 双方都无宠物时，空屋可进可出，没有精灵。

## 10. 已确认的选择

| 项 | 选择 |
|----|------|
| 房屋归属 | 两人共用一座；装饰是两只宠物解锁的合集 |
| 进出 | 星露谷式：默认室外，点门进屋，再点门出去 |
| 宠物位置 | 按自然日固定，第二天再随机 |
| 房间 | 固定小农舍：室外院子 + 室内客厅/卧室，房屋不随等级变大 |
| 家具来源 | 兔、牛各有风格图鉴（不按共用一张总表） |
| 实现 | HTML + CSS 像素布景，不用画布、不用整图背景 |
