# 09 乐园用 Blender 重构：可行性与方案

前提：乐园要做成 **真 3D**，换可玩性，不只换皮。**先做 Web**（Next.js 里实时 WebGL）。iOS 原生是很后面的一步，到时复用同一套 glTF，现在不为它设计交互、不为它出 USDZ。

结论：**近期唯一产品是「Blender 资产 → Web 实时 3D 乐园」。** 引擎用 glTF + three / R3F。CSS 像素屋是过渡。产品规则（两人一屋、点门、上下楼、等级家具、宠物）不动。

现网 `docs/乐园建筑美术设计.md` 锁死 HTML+CSS、禁止画布。走 3D 必须改那一节：乐园页允许 WebGL。对照资产见 [06](./06-atlas积木实例化.md)、[07](./07-atlas资产目录.md)、[08](./08-blender插件.md)。风格见 [风格总览](./风格总览.md)。

## 1. 现在乐园实际是什么

| 层 | 实现 | 职责 |
|----|------|------|
| 产品 | `dream-client.tsx` + Prisma 宠物 | 进出门、楼层、宠物落点、解锁家具 |
| 场景声明 | `src/lib/park/scenes.ts` + `yard`/`house`/`basement` | 对象清单，锚点是格子 |
| 几何语义 | `object.ts` 的 `atom` / `prism` | 3/4 斜俯视：亮顶 + 南（或东）竖面 |
| 材质 | `materials.ts` → CSS class | 灰泥、赤陶、沙、水 |
| 绘制 | `SceneRenderer` | 每个原子一个 `absolute` 的 `div` |
| 等级家具 | `park/furniture/*` + `FurniturePiece` | 兔/牛各 10 件，CSS `Iso` 方块 |
| 宠物 | `PixelPet` 叠在格子上 | 不是 3D |

热区是 UI，不是网格：门 ≥ 44px。测试锁死泳池、门、瓦顶等原子（`park-scene.test.ts`）。仓库 **没有** three / R3F / glTF。

一句话：现在是 **假 3D 积木**。可玩的只有切层、点门、点宠物。转圈、揭楼、在屋里走、拖家具、宠物绕障碍，CSS 做不了，也不该硬做。

## 2. 为什么 3D 值得做（可玩性，不是好看）

2D 框能讲「这是我们的屋」。3D 才能把屋变成 **可操作的地方**。这些能力 **全部先在 Web 上做满**，不要留给以后的 App。

| 玩法 | 2D CSS | Web 实时 3D |
|------|--------|-------------|
| 绕屋看后院 / 从海里看立面 | 做不到（只有一个假俯角） | 轨道或限定偏航 |
| 进门 | 换一整页布景 | 相机 tween 进门厅，空间连续 |
| 上下楼 | 按钮切场景 | 楼梯走、揭屋顶、剖楼（爆炸两段，见 [06](./06-atlas积木实例化.md)） |
| 家具 | 槽位贴图 | 解锁后 **摆、转、靠墙**；以后可换墙纸 |
| 宠物 | 格子站桩 | 地面寻路、点哪里走过去、进屋跟着相机 |
| 两人同屋 | 两个精灵叠层 | 各自站位、以后实时出现（仍是后话） |
| 天气 / 昼夜 | 换 class | 同一网格换灯、换天 |

Web 要真的能转、能点、能进门，不是「等距静帧 + 换页」。手机浏览器上轨道做限幅（例如偏航 ±40°）、像素比封顶，那是性能，不是把玩法砍掉。背面没做好就先锁角度，补网格后再放开。

## 3. 资产与 Web 运行时（iOS 后置）

现在只打通左边这一支：

```
.blend（Blender 5.2，Collection 分楼层 / 家具）
        │
        ├─ park.glb（共享 mesh，Web 主资源）
        └─ park-scene.json（摆放、解锁 id、热区世界坐标、相机预设）
                │
                ▼
        Next.js 乐园页
        three / R3F（dynamic，关 SSR）
        鼠标 / 触摸轨道、HTML 按钮叠层
```

iOS（很后面）：同一 `park.glb` + 同一 json → RealityKit / USDZ。那一步再写原生手势和 AR。当前 **不** 做：USDZ 管线、Swift 查看器、WebView 套壳、为 App 预留的残缺交互。

json 不要写 `.blend` 路径。Web 只认 glb 节点名，和现在 `FurnitureObject.meta.id` 对齐。

导出：Blender glTF，应用修改器，网格名稳定。单位米。Y-up / Z-up **在 json 里写死**（Atlas 的 Rx(π) 就是这个坑，见 [06](./06-atlas积木实例化.md)）。以后 iOS 按同一约定转，现在不必双端各猜。

格子：现网 60×80、1 格 8px。3D 建议 **0.25 m/格**（面宽 15 m），门洞对齐现网南门语义。`prism()` 作废。

## 4. 约束（渲染可以换，产品不能拆）

1. 两人一座屋；默认院子；点门进出；上下楼；出门回到一楼。
2. 家具按宠物等级解锁，兔/牛两套，**槽位从「贴在固定像素」升级为「可摆，但有默认摆法」**——摆放第一期就在 Web 做，不攒给 iOS。
3. 宠物当天抽房间，能点出名字；3D 里可以走，还是那两只。
4. 日记站的乐园入口仍是 `/me/park`。3D 失败时 CSS 可短暂回退，不是长期双栈。
5. 室内视觉锁 [粉彩剖屋](./10-粉彩剖屋.md)（族 E）：切开的盒子、桃/薄荷/奶油、中大倒角。外壳要不要南加州是另一件事，**进了门不要画成便利店或和风夜景**。

## 5. 可行性（先只看 Web）

| 问题 | Web 3D |
|------|--------|
| 引擎 | three / R3F，`next/dynamic` 关 SSR |
| 包体 | 整园实例化，单件家具 < 1MB，共享 mesh |
| 点击 | raycast；楼层 / 出门仍可用 HTML 按钮（无障碍） |
| 宠物 | 先 billboard 现有像素图，后低模 |
| 楼层 | 显隐 Collection 或剖切，json 驱动 |
| 测试 | 原子 CSS 测试作废；改测 json 锚点 + glb 存在 |
| 规范 | 必须改「禁止画布」 |

精灵 PNG、分层底图只当 Blender 对照，不当主产品。载体从第一天就是 **GLB**。

## 6. 推荐节奏（全部是 Web）

### 步 1 — 空屋 + 场景图 + Web 加载

Blender：LA 小屋 + 院，低模。正交相机只给工作室预览。

Collection：`COL_YARD` `COL_HOUSE_L0` `COL_HOUSE_L1` `COL_HOUSE_L2` `COL_FURN` `CAM` `ENV`。

产出：`park.glb`、`park-scene.json`（相机预设：院、门厅、一楼、二楼、负一）。

Web：最小查看器，先锁等距角，验证加载和楼层显隐。可先挂 `/me/park/sandbox`，再切主路径。

### 步 2 — Web 可玩性最小集

1. **进门**：点门 → 相机进 foyer，不是换页。出门反向。
2. **剖楼 / 切层**：按钮或滑杆揭屋顶；进室内隐藏外墙南面。
3. **点选**：门、楼梯、宠物、已解锁家具；空点取消。
4. **轨道**：桌面拖转；手机限偏航，背面没做好就锁住。

宠物先用现有像素图 billboard，站位改世界坐标。

### 步 3 — 家具在 Web 里从贴槽变成摆件

20 件在 Blender 做，节点名 = `FurnitureObject.meta.id`。默认矩阵写进 json（从现 `slot` 换算）。解锁逻辑不动。

随后在 **Web** 开拖到地面、吸附、旋转 90°。不要把摆手放进「以后 App 再做」。

材质：Principled、少贴图、Roughness 0.4–0.5、Bevel 中等。一种灯一份 mesh，多槽实例化。

### 步 4 — 宠物在地面上走（仍是 Web）

简单导航网格（院子 + 各层平面碰撞）。点地面走过去。不要一开始做攀爬、开门物理。

### 步 5 — `/me/park` 切 3D，CSS 降级

主路径走 WebGL 查看器。`SceneRenderer` 留作 `?park=css` 或检测无 WebGL。改 `乐园建筑美术设计.md`。原子测试改场景图快照。

### 步 6 — iOS（很后面，本文不展开工期）

同一 glb + json。原生查看器、手势、可选 AR。Web 玩法已经成立，App 是另一块触控表面，不是功能出处。

## 7. 数据怎么接

```
解锁 / 宠物 / 两人关系     现有 API
park-scene.json            摆放与相机
FurnitureObject.meta       id、等级、图鉴文案（已有，不改）
外观                       只在 glb 节点里，不再走 CSS Iso
```

图鉴页可以仍是 2D 列表，点进去进 3D 园。

## 8. 工作量粗估（不含 iOS）

| 范围 | 量级 | 风险 |
|------|------|------|
| 步 1 空屋 + glb + json + Web 加载 | 一两周 | 坐标轴、色管、移动端包体 |
| 步 2 进门 / 剖楼 / 点选 / 轨道 | 一两周 | 相机状态、触摸和页面滚动抢手势 |
| 步 3 二十件家具 + Web 摆放 | 一两周 | 风格不统一、吸附难用 |
| 步 4 寻路 | 数日到一周 | 网格洞、跨层 |
| 步 5 切主路径 + 回退 | 数日 | 低端机、无障碍 |
| 步 6 iOS | 另开一期 | 不进当前范围 |

资产管线熟了之后，加一张椅子主要是建模时间，不是再写一套 CSS。

## 9. 风险

- **页面手势**：乐园在日记站里，轨道拖转会和滚动、返回手势打架。查看器要明确 pointer capture，按钮进门/上楼必须始终在 HTML 上。
- **世界观**：可玩性不要求抄卡通城市全套；外形仍建议南加州小屋，微缩只在 Bevel 和比例。
- **包体与电量**：实例化、合批、移动端像素比封顶；整园不要学 P1 那种 34MB bin。
- **无障碍**：3D 里键盘/读屏比 CSS 差。楼层、进门、点宠物必须有按钮替代。
- **MCP**：建模用 GUI；批量导出用 CLI。`-b` 开不了 MCP。
- **许可证**：不进 Atlas P1 网格。
- **过早 iOS**：现在分叉 USDZ / 原生状态机会拖死 Web。资产命名保持干净即可，够以后接。

## 10. 拍板清单

3. CSS 回退保留多久？  
4. 改 `乐园建筑美术设计.md` 第 3 节的具体措辞。

室内家具未拍板外形前，按族 E 做（已有胡萝卜灯样件）。未定外壳前，步 1 的空屋对照可以先出剖盒，不铺二十件。
