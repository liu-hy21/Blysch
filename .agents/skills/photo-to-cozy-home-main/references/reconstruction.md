# 照片与户型推导

## 证据表

为每张照片保留简短记录：文件编号、候选房间、拍摄朝向线索、可见门窗、共同家具/墙面、相邻空间、确认程度。同一面镜子或玻璃里的反射不是另一个房间；超广角形变不能直接当成尺寸。

按重复锚点拼接：门框颜色与开向、床头墙、衣柜侧面、同一幅画、厨房推拉门、地面材质分界、窗帘和窗外景物。照片顺序只能作弱线索，不能作为空间邻接证明。

每项结构信息记录三种状态：
- 已确认：用户说明、适用的户型图，或照片中直接可见的关系。
- 有依据的推断：跨照片锚点一致，但缺少完整连接视角。
- 未知：没有证据，不虚构确认度百分比。

## 有户型图

先确定图向、房间编号、尺寸链含义、墙体与门窗符号，再匹配实拍。区分尺寸标注是轴线、净宽还是外轮廓；相邻尺寸不吻合时保留估计，不强制制造精确面积。

实际装修可能移动非承重隔墙、干区、柜体或改变房间用途。以用户明确说明的现状覆盖原图对应部分，保留变更记录。户型图标的“卧室 B”不能自动命名为次卧；房名使用用户称呼。

## 仅有照片

先建立拓扑图，再求几何：
1. 识别实际房间及开放空间，不把同一空间的反向照片拆成两个房间。
2. 将每个门洞连到两个空间，记录“由哪个门向哪边转”；允许入口短廊、干区和套内卫浴作为子分区。
3. 确定外窗所在墙面和主要家具相对墙的关系。
4. 用地砖、床、门等常见物体辅助估计比例；除用户给出实测值外，这些都不是标尺。
5. 在无重叠、房门连通和窗外合理的条件下拼接轮廓。若仍有镜像、旋转或房间位置的多解，用一张标注候选图和具体问题消除歧义。

缺少一扇关键门的另一侧视图时，优先问该门通往哪里；缺少柜体宽度时可先估算。避免为了微小物件暂停整个项目。

## 统一数据约定

在项目中选择并注明坐标约定，例如 x 向图右、z 向图下、y 向上；图上方不默认是北。布局数据至少表达：
- 稳定 roomId、用户房名、边界（矩形或多边形）、父套间、照片引用。
- 实体墙段及两侧房间、墙厚、内外表面；非矩形和多楼层按实际需求扩展。
- 门/开放连接/窗的墙段、位置、尺寸、高度与门扇朝向；外门不自动扩展室内可走域。
- 家具局部姿态、实际包围范围、落地障碍、交互接近点与座位锚点。
- 结构信息的证据来源与未知项。

平面图和模型从这份数据生成。保留显示用房间名与稳定 ID 的区别，不能让 UI 文案决定几何坐标。

## 确认用语示例

- “我看到粉墙卧室和木床卧室，它们分别是主卧还是次卧？”
- “站在入户门朝里看，餐厅在左侧吗？客厅是否与它连成开放空间？”
- “从卫生间门外朝里看，洗手台、马桶、淋浴各在哪侧？前后顺序如果记不清，可以先只确认左右。”

已回答的内容记录下来，后续不重复问。用户没有尺寸时仍可交付估计模型，标清比例可校准即可。
