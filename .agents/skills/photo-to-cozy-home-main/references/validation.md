# 验收场景

按当前项目范围运行检查；已有通过的检查无需无变化反复重跑。结果记录真实测试范围，不使用预设的“全部通过”数字。

## 结构和几何

- 所有房间与证据表、用户命名匹配；主次卧对调时检查实际床、柜、照片和相邻连接，而非只检查名称。
- 房间地板无错误重叠/漏缝，共用墙没有重复表面，门窗是真实开口。
- 开放公共区在完整墙体模式下仍无虚构梁框或碰撞边界。
- 家具完整几何在其允许空间内，柜门开合无冲突；画框和其他挂墙物完整落在可用墙面内，避开门窗。
- 旋转四个方向、完整墙体/剖面、全屋/单房间切换后几何与装饰一致。
- 平面图与三维模型同源，照片索引正确，残余估计项可追溯。

## 导航回归

- 从公共区到每个房间、每个活动接近点可达；实体墙、家具与室外不可穿越。
- 两人在窄门相向、交换目标、同赴书桌、从同一房间出发、一个离座被另一个阻挡时，最终能完成或合理重选活动。
- 主卧床边到套内卫浴及返回路线通过正确门洞，不能穿过衣柜或隔墙。
- 多个固定种子各模拟数分钟连续自主活动，检查位移进展、到达次数、人物间距、静态碰撞和长期等待。不能仅以动画循环仍运行判定未卡住。
- 布局修改后的旧保存位置可安全恢复；房间视图切换不改变人物世界位置。

## 浏览器实际操作

启动应用并看真实渲染，检查控制台错误。至少验证：
1. 全屋选择各房间、进入/返回，套间与卫浴单独查看。
2. 旋转、缩放、俯视与还原，完整墙体/剖面切换。
3. 电脑开关有屏幕变化，灯和台灯真实改变局部照明，衣柜反复开合。
4. 手动移动、闲置恢复自主活动、跨房间完成一个活动、坐下和起身。
5. 清晨/正午/黄昏/夜晚与天气切换，夜晚开灯，窗外与室内联动。
6. 若交付支持移动端，按下面的移动端验收检查实际可用区域与触控。

有截图时保存当前全屋、平面图与本次修改重点；历史截图明确标为历史，不能用旧截图代表新布局。工具限制导致无法运行某项时，指出具体未测项与可复现操作步骤。

## 移动端验收

按用户设备选择代表性的窄屏、常见手机、短横屏及桌面尺寸，例如 320 像素宽窄屏、390 像素宽手机与约 844 × 390 的横屏；这些是示例，不是固定设备清单。

- 默认菜单收起时，房屋占据主要可用区域；展开每个面板后仍可观察和操作房屋，内容不被底部导航或安全区截断，面板底部操作可滚动到达。
- 检查关闭、重复点击入口、切换面板、一次性操作后收起、连续调整时保持，以及专心看房后的菜单恢复。检查焦点与展开状态是否一致。
- 全屋与单房间在面板收放、旋转屏幕和沉浸切换后均无意外裁切；用户缩放、平移不会被持续重置。
- 按钮保持独立触控区域和一致间隔。用实际渲染后的边界（如 getBoundingClientRect）测量相邻间距，并结合截图确认，特别检查不同父容器中的连续按钮。不能仅检查 CSS 声明。
- 手机与桌面断点来回切换后，控件位置、监听事件、家具开关和选择状态正常；没有重复控件或误绑定到帮助弹窗。
- 实测触摸旋转、双指缩放、抬指与取消操作不会误触点击。仅调整浏览器视口或用鼠标拖动，不代表真机多指、Safari 浏览器栏或系统安全区已通过；工具不支持时明确列出未测项。

单纯按钮间距等局部样式修复，构建加针对性的移动端视觉和边界检查通常足够；只有修改影响布局几何、导航或相机时才扩大相关回归，不为一行样式重复整套仿真测试。

## 交付核对

确认启动命令和预览地址可用，打包内容来自当前代码版本。导出的平面图也已更新。整理少量仍需用户确认的空间关系，避免把未测尺寸写成实测值。修复可见问题后再交付，检查正常则停止扩大测试范围。

区分本地修复与线上发布。发布依据用户在会话中给出的授权与范围，不因浏览器正在显示线上地址就推定授权；已有同站、同范围授权不反复询问。发布后验证实际线上资源与本次构建一致，沿用已有照片时不重复上传私有素材，并保留可回退版本。
