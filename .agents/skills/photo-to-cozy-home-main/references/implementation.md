# 建模与交互约束

## 建筑与坐标

二维图、三维建筑、人物导航共用几何数据和门洞定义。相邻房间的共线墙段合并/切分后只生成一个实体，可为两面使用不同墙色，不能用重叠薄墙模拟两种颜色。T 字连接、墙角、踢脚线和顶线也避免共面闪烁。

房间语义边界不等于墙。连通的客餐厅、玄关、走道可以分别点选，但开放连接处不生成墙楣、门框、立柱或隐形障碍。真正的门窗从墙体几何开洞，地板连续，门扇转轴与开向匹配。

单房间视图只改变可见性和相机，不重新创建一套不同坐标的世界，不把人物瞬移进房间。保留完整墙体模式；剖面随相机缩短遮挡墙，让旋转时看得见内部。导航仍使用完整物理墙体。

如复用家具模板，家具网格、碰撞、座位、接近点、灯光和装饰一起经过同一平移/旋转/缩放；不要再次变换已按世界坐标生成的建筑。变换后的实际网格范围也要检查，不能只校验声明的家具占地。

## 家具与挂墙物

几何简化保留识别锚点：床头墙色、床与窗的关系、衣柜连梳妆台、U 形厨房、餐边柜、沙发与电视相对位置等。统一Q版比例与材质，避免每个房间单独换风格。

画框、镜子、磁贴板等绑定实际实体墙段，验证完整几何的宽高范围，不只验证中心点。留边距、避开门窗、柜体和层板；贴近墙面且正面朝室内。没有足够墙面时移至有证据的墙、缩小或省略次要装饰，不悬空放在开放通道中。承载墙在剖面中隐藏到装饰以下时，装饰同步隐藏；恢复时回原位置。

衣柜有真实空腔与内部层板、挂衣等。按照片选择平开或移门；门有动画、可重复开合、可从模型和控制面板一致触发。移门限制在轨道内；平开门占地随动画更新并让人物避让，不能让门穿过人或家具。交互射线不能穿透实体墙误选背后的物品。

## 人物与活动

同一导航系统服务手动和自主模式：以人物半径膨胀实体墙和落地家具，门洞净宽足够才可通过。路径在转角、门口及斜向采样检查，不能切过墙角；高位热水器、吊灯不阻塞脚下可走空间。

活动具有可达的接近点和独立座位/使用锚点，先走到接近点，再连续坐下/站起；离座先回可走点再寻路。坐姿允许进入指定座位范围，但不取消其他家具碰撞。

两位人物存在动态占地与活动点占用规则。迎面时采用稳定让行优先级，允许等待、侧让或退到最近安全位置，不能双方每帧对称重规划而永久卡住。检测一段时间内没有位移/没有到达的情况：重规划、让行或放弃不可达活动换目标；不要用瞬移或关碰撞“解卡”。

手动指令立即覆盖本人自动目标；闲置一小段时间后恢复自动活动，并让 UI 表明控制状态。自动模式可随机选择休息、学习、喝水等，也可用确定的作息队列。随机测试使用可设定种子以便复现。单独查看房间不限制人物的跨房间活动。

## 昼夜和光线

时间和天气驱动一致的环境光、太阳/月亮方向与颜色、窗外景色。夜晚降低自然光但保留可操作的可见度。内灯有独立开关，台灯使用局部光源照亮桌面，阴影/遮挡不能无视墙体。避免只叠一张黄色贴片冒充开灯。

日光运动依据示意时间即可；没有真实朝向、地理位置与气象信息时，不称为真实日照模拟。室内雨水不穿入封闭房间。每个空间是否有窗由证据决定。

## 操作与性能

区分拖动旋转和点击选择，避免放开拖动时误触开关。恢复视角要适配当前房间的真实范围和朝向。所有视图共享灯、柜门和人物状态；有持久化时为布局版本变更处理旧人物坐标，避免刷新后出生在新墙里。

复用材质与几何，对地板重复单元考虑实例化，限制阴影灯数量和像素比。根据实际浏览器验证加载速度、帧率与触控可用性，不把低端设备无限增加细分。若 WebGL 不可用给出明确提示和平面图入口。

## 移动端界面与画布

手机默认状态以观察房屋为主，仅保留紧凑的必要导航和工具入口。将房间选择、家具互动、时间天气与人物生活、视角工具组织为可收放面板，具体入口数量沿用项目需要。同一时间只展开一个面板，避免顶部导航、家具条、生活栏和相机工具同时占据视口。

- 竖屏可用底部抽屉，横屏可用侧面板；展开后按实际剩余区域布局画布并调整相机，不能只把桌面控件缩小叠在房屋上。面板内容可滚动，短屏也能访问最后一个操作。
- 选房、完成视角选择或进入行走模式等一次性操作后可自动收起；灯光、衣柜、时间等需要连续调整的操作保留面板。支持关闭按钮、再次点击当前入口收起，以及键盘 Escape；维护 aria-expanded、aria-controls 和关闭后的合理焦点。
- 提供“专心看房”或等效入口，隐藏非必要菜单与密集标记，同时始终保留清晰的恢复入口。手机可默认减少房间标记和人物气泡，但保留按需显示方式。
- 使用动态视口高度和安全区边距，适配浏览器栏、刘海和底部手势区；避免固定最小高度造成短屏溢出。触控目标通常至少约 44 CSS 像素，滑杆要有足够的实际触摸区域。

桌面和手机复用控件逻辑及状态，不能因切换布局丢失事件、开关值或人物选择。若将现有 DOM 控件搬进面板，记录原位置并在返回桌面时恢复；选择器限定具体组件，避免误选帮助弹窗内的同名按钮。

相机依据画布的实际可用宽高和模型真实轮廓取景，考虑墙高、底座及 L 形户型的空白区域，同时约束宽度和高度。全屋、单房间、面板展开/收起、横竖屏和专心看房模式均应完整取景。布局变化时更新取景，不在每帧重置用户主动的缩放与平移。

按钮之间保留一致、可辨认的空隙，优先使用共同容器的 gap 或已有间距变量。检查的是相邻可点击元素的实际边界，而不是某个按钮自身是否写了 margin；按钮处于不同包装容器或被搬入抽屉时，尤其容易丢失间距。沿用项目视觉尺度，不将单次修复的像素值写成所有项目的固定要求。

跟踪触摸指针，双指操作开始后作废本轮点击候选，pointercancel 时清理状态；最后一个手指抬起不能误触家具、房间或行走指令。拖动与点击判定在触屏和鼠标上保持一致。
